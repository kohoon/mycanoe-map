# 2026-09-11

## 한 일

- 카카오 로드뷰 모달에 `URL 공유` 버튼을 추가했다.
- 장소에서 연 로드뷰는 `place=<장소ID>&view=roadview`를 기본으로 공유하며, 로드뷰 안에서 이동한 실제
  파노라마 좌표와 파노라마 ID, 수평 방향, 기울기, 줌을 URL에 함께 기록한다.
- 공유 URL을 열면 같은 카카오 파노라마와 시점을 자동 복원한다. 장소 ID가 없는 로드뷰도 현재 좌표로 공유한다.
- 로드뷰 모달에 같은 위치를 네이버 거리뷰·항공뷰, Google Street View·항공사진, Mapillary,
  KartaView에서 확인하는 비교 버튼을 추가했다. 비교 서비스는 새 탭으로 열어 현재 카카오 화면을 유지한다.

## 결정·근거

- 네이버 지도 웹앱은 `X-Frame-Options: DENY`, Google Maps는 `SAMEORIGIN`, Mapillary 웹앱은 `DENY`로
  외부 iframe 표시를 막는다. 네이버 공식 파노라마 SDK도 NCP 클라이언트 키와 등록 도메인이 필요하다.
  따라서 현재 키가 있는 카카오는 인앱으로 유지하고 다른 제공처는 동일 좌표의 공식 웹 화면을 새 탭으로 연다.
- Google은 공식 Maps URL의 `map_action=pano`와 `viewpoint`를 사용하며, 카카오의 현재 수평 방향·기울기·
  줌도 가능한 범위에서 Google의 `heading`·`pitch`·`fov`로 변환한다.
- 네이버 공식 파노라마 문서에서 거리뷰·항공뷰와 두 보기의 전환, 주변 항공뷰 지점(`FlightSpot`) 지원을
  확인했다. Google 항공사진은 공식 Maps URL의 `basemap=satellite`로 열며 360도 항공 파노라마와 구분한다.
- Mapillary와 KartaView는 사용자 촬영 기반 자료여서 강변 비포장 접근로나 지방 도로에서 국내 상용 거리뷰를
  보완할 가능성이 있지만, 특정 좌표의 촬영물 존재를 보장하지 않는다고 화면에 명시한다.

## 검증

- `python3 tools/build_map.py`, `python3 tools/build_map.py test`, 생성 HTML 4개의 인라인 JavaScript
  `node --check`, 기존 내수면 금지구역 회귀 테스트를 통과했다.
- Playwright 모바일 검증에서 `place=149&view=roadview` 공유 URL이 파노라마 ID `1196335174`와 시점
  `pan=123, tilt=4, zoom=1`을 그대로 복원하고, 시스템 공유 payload가 URL 한 필드만 갖는지 확인했다.
- 로드뷰 안에서 이동한 실제 파노라마 좌표가 공유 URL과 네이버·Google·Mapillary·KartaView 비교 링크에
  반영됐다. 외부 비교 버튼 5개가 HTTPS 새 탭으로 열리고 JavaScript 오류는 0건이었다.
- 모바일 390px에서 모달 폭 390px·파노라마 폭 362px/높이 574px, 데스크톱에서 모달 폭 900px·
  파노라마 높이 640px를 확인했다. 공유 링크 모달은 로그인 관문보다 위에 표시되고, 닫으면 `place`만 남는다.
- 허용 범위 밖 좌표(`0,0`)는 자동 로드하지 않는 음성 회귀도 확인했다.

## 로드뷰 제공처별 존재 확인

- 제공처 이름이나 외부 링크만 있다는 이유로 해당 좌표에 로드뷰가 있다고 간주하던 비교 버튼을 수정했다.
- 네이버 거리뷰·항공뷰와 Google Street View는 각각 Naver Maps API 키와 인증된 Google Street View
  metadata API가 없으면 좌표별 존재를 정확히 판정할 수 없다. 현재 운영본에서는
  링크를 무조건 열지 않고 `확인 키 필요`로 비활성 표시한다.
- 사용자 촬영 기반 Mapillary와 KartaView는 촬영 품질 검토 후 비교 목록과 조회 코드에서 제거했다.
- Google 항공사진은 360도 파노라마가 아닌 지도 기본 레이어이므로 `기본지도`로 구분해 선택 가능 상태를 유지한다.
- 공유 URL의 카카오 파노라마 ID도 그 자체를 현재 존재 증거로 쓰지 않는다. 현재 좌표에서 카카오
  `getNearestPanoId`가 파노라마를 다시 확인한 뒤에만 공유된 파노라마 ID와 시점을 복원한다.

### 검증

- 생성 HTML 4개에서 Mapillary·KartaView 이름과 URL이 남아 있지 않은지 확인했다.
- 제공처 이름·링크나 공유 파노라마 ID만으로 현재 촬영물이 있다고 판정하지 않는 음성 회귀 테스트
  `tests/test_roadview_providers.py`를 추가하고 통과시켰다.
- 모바일 390px 로드뷰 모달에서 네이버·Google Street View는 `확인 키 필요` 상태로 비활성이고,
  비활성 버튼 함수를 직접 호출해도 외부 창을 열지 않는 것을 확인했다.
- 360도 로드뷰가 아닌 Google 항공사진만 `기본지도`로 구분되어 같은 좌표 URL을 열며, 브라우저
  JavaScript 오류와 페이지 오류는 각각 0건이었다.
